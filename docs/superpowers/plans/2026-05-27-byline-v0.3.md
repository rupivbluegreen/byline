# Byline v0.3 — Multi-provider LLM support

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.

**Goal:** Let users point byline's LLM-touching commands at any of three backends — Anthropic Claude (current), OpenAI / GPT, or a self-hosted OpenAI-compatible endpoint (Ollama / vLLM / LM Studio / llama.cpp) — without changing how the rest of the tool behaves.

**Constraint:** All v0.1 + v0.2 framing rules and acceptance criteria still pass. Banned-phrase post-processing runs on every provider's output. No top-level imports of any LLM SDK.

---

## Architecture

A single new abstraction lives in `byline/llm_provider.py`:

```python
class LLMProvider(ABC):
    name: str   # "anthropic" | "openai"
    default_model: str

    @abstractmethod
    def generate(
        self,
        system: str,
        user: str,
        *,
        max_tokens: int,
        temperature: float,
        model: str | None = None,
    ) -> str: ...
```

Two concrete implementations:

1. **`AnthropicProvider`** — wraps the existing `anthropic.Anthropic` client. Default model: `claude-sonnet-4-5`. Reads `ANTHROPIC_API_KEY` from env. Lazy imports `anthropic` inside `__init__` / `generate`.

2. **`OpenAIProvider`** — wraps `openai.OpenAI` client. Default model: `gpt-4o`. Reads `OPENAI_API_KEY` from env. Optional `OPENAI_BASE_URL` env var redirects all calls to a self-hosted endpoint (Ollama, vLLM, LM Studio, etc — they all expose the same OpenAI-compatible REST surface, so this single provider covers all of them). When the base URL is overridden, the default model becomes whatever the user sets via `BYLINE_LLM_MODEL`.

Selection happens via a single factory:

```python
def get_llm_provider() -> LLMProvider | None:
    """Resolve the configured provider from env. Returns None if no
    provider can be constructed (missing SDK or missing key)."""
```

Env var contract:

| Variable                | Default        | Purpose                                            |
|-------------------------|----------------|----------------------------------------------------|
| `BYLINE_LLM_PROVIDER`   | `anthropic`    | `anthropic` or `openai`                            |
| `BYLINE_LLM_MODEL`      | provider-default | Overrides the model identifier                   |
| `ANTHROPIC_API_KEY`     | —              | Required for `anthropic`                           |
| `OPENAI_API_KEY`        | —              | Required for `openai`                              |
| `OPENAI_BASE_URL`       | OpenAI's       | Self-hosted endpoint, e.g. `http://localhost:11434/v1` for Ollama |

Self-hosted setup is just `BYLINE_LLM_PROVIDER=openai OPENAI_API_KEY=ollama OPENAI_BASE_URL=http://localhost:11434/v1 BYLINE_LLM_MODEL=llama3.2`. No new CLI flags, no new code paths.

## Refactor of existing code

The current LLM call sites all hold an `anthropic_client` parameter. We rename and re-type:

- `byline/llm.py`: replace `_call_anthropic(client, ...)` with `_call_provider(provider: LLMProvider, ...)`. The prompt constants (`ALIGNMENT_SEMANTIC_SYSTEM_PROMPT`, `QUESTIONS_SYSTEM_PROMPT`, `CHAT_SYSTEM_PROMPT`, `ALIGNMENT_SUMMARY_PROMPT`) stay byte-identical. `get_anthropic_client()` becomes a thin compatibility shim that delegates to `get_llm_provider()` and returns the provider (typed as `Any` to keep call sites loose). `qualitative_pass(result)` continues to work; it now uses the resolved provider.

- `byline/alignment.py` `run_semantic_alignment(repo_path, anthropic_client)` → `run_semantic_alignment(repo_path, provider)`.

- `byline/questions.py` `generate_questions(audit, repo_path, anthropic_client, n)` → `generate_questions(audit, repo_path, provider, n)`.

- `byline/chat.py` `run_chat_session(audit, repo_path, anthropic_client)` → `run_chat_session(audit, repo_path, provider)`.

- `byline/compare.py` `audit()`: replace `from byline.llm import get_anthropic_client` with `get_llm_provider`. Wiring stays the same — pass through.

- `byline/cli.py` `questions` and `chat` subcommands: read `get_llm_provider()` instead of `get_anthropic_client()`. Update the error hint when the provider isn't available — it now mentions all three setup paths.

The parameter rename is a breaking API change for any external caller of `byline.alignment.check_alignment` etc., but byline is v0.2 alpha and the only callers are internal. The rename is documented in the CHANGELOG.

## Dependencies

`pyproject.toml` `[project.optional-dependencies] llm`:

```toml
llm = [
    "anthropic>=0.40",
    "openai>=1.0",
]
```

Both clients land together when the user installs `byline-audit[llm]`. Self-hosted users don't need anything extra — the `openai` SDK speaks to any OpenAI-compatible endpoint over HTTP.

## Tests

New file `tests/test_llm_provider.py`:
- `AnthropicProvider.generate` happy path with mocked `anthropic.Anthropic` client.
- `OpenAIProvider.generate` happy path with mocked `openai.OpenAI` client.
- `OpenAIProvider` with `OPENAI_BASE_URL` override — the client is constructed with the override.
- `get_llm_provider()` returns `AnthropicProvider` when env is default + key set.
- `get_llm_provider()` returns `OpenAIProvider` when `BYLINE_LLM_PROVIDER=openai` + key set.
- `get_llm_provider()` returns `None` when no key set for the configured provider.
- `get_llm_provider()` returns `None` when the SDK for the configured provider isn't installed (simulate via `importlib.import_module` raising).
- Banned-phrase scrubbing is applied to the output regardless of provider.

Update existing tests:
- `tests/test_llm_v02.py` — switch fixtures from "mock anthropic_client" to "mock provider"; assert the same prompt + parameters reach the provider.

CI: the existing `test-base-install` job already verifies that the package imports without `anthropic` loaded; we extend that assertion to also verify `openai` is not loaded. Both must stay lazy.

## Out of scope for v0.3

- Per-call model override via CLI flag (env var is enough for now).
- Streaming responses.
- Cost reporting / token accounting beyond the existing DEBUG logs.
- Gemini, Cohere, Mistral, etc. — the OpenAI-compatible provider covers most of them when they expose that interface; we can add native providers in v0.4 if needed.
- Multi-provider concurrent calls (e.g., run alignment with Claude + GPT and diff the results). Interesting but distinct feature.
